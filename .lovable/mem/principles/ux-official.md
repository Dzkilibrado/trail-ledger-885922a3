# Princípios oficiais de UX do TrailBook

Aplicar em TODA decisão de UX, acima de qualquer preferência visual ou técnica.

## 1. Três perguntas obrigatórias antes de adicionar qualquer elemento
1. Resolve um problema real do usuário?
2. Será usado com frequência?
3. Se removido, a experiência piora?

Se qualquer resposta for NÃO → o elemento não deve existir. Nunca preencher espaço.

## 2. Regra do usuário cansado
Cenário permanente de design: motociclista voltando de trilha/viagem/treino, cansado, no celular, possivelmente com uma mão só. A interface deve ajudar — nunca obrigar a pensar, procurar ou navegar por menus.

## 3. Uma tela = uma decisão
Cada tela principal responde a UMA pergunta:
- **Cockpit** → "Como está minha motocicleta?"
- **Central da Moto** → "O que desejo fazer agora?"
- **Check-up** → "Existe algum problema?"
- **Componentes** → "O que precisa de manutenção?"
- **Histórico** → "O que aconteceu anteriormente?"
- **Documentos** → "Quais documentos preciso consultar?"

Tela que tenta responder várias perguntas → simplificar.

## 4. Menos é mais
Poucas ações bem organizadas > dezenas de opções competindo por atenção. Novas funcionalidades entram sem aumentar complexidade.

## 5. Decisão acima da informação
Antes de exibir informação, perguntar: "isso ajuda o usuário a decidir?" Se não, pertence ao 2º nível de navegação, não à tela principal.

## Como aplicar
- Em cada proposta de UX (Fase A, B, C, futuras), validar cada elemento contra as 3 perguntas e a pergunta única da tela.
- Preferir remover a adicionar. Preferir bottom sheet / 2º nível a empilhar na tela principal.
- Preservado em toda evolução futura.
