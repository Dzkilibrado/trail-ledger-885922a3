# v1.7.7 — Fluxo Documental do Recibo Inteligente (BACKLOG)

Status: **aprovado conceitualmente, NÃO implementar agora** (aguardando renovação de créditos).
Retomar somente após confirmação explícita do usuário. Não executar migration, RPC, alteração de banco ou componentes até lá.

## 1. Subestado sem novo enum
- Manter enums de status atuais (`draft`, `issued`, `awaiting_acceptance`, `completed`, `cancelled`, `revoked`, `superseded`).
- Adicionar `smart_receipts.signed_document_received_at timestamptz null`.
- Estado visual derivado de `status` + `signed_document_received_at` + existência de versões documentais.
  - `issued`/`awaiting_acceptance` + `null` → "Aguardando assinatura das partes".
  - `issued`/`awaiting_acceptance` + preenchido → "Documento assinado recebido".

## 2. Documento assinado NÃO substitui aceite
- Upload é apenas evidência documental.
- Não preenche `seller_accepted_at`, `buyer_accepted_at`, não conclui transferência, não altera `motorcycles.owner_id` nem `ownership_history`.
- Máquina de estados atual segue comandando a conclusão.

## 3. Versionamento em `motorcycle_documents`
- Adicionar `receipt_id uuid null REFERENCES smart_receipts(id) ON DELETE SET NULL` + índice.
- Versão 1 = original TrailBook; Versão 2 = assinado (`parent_id` → v1, `is_current=true`).
- Antes de implementar: confirmar suporte a `bucket`, `storage_path`, `file_name`, `doc_type`, `version`, `parent_id`, `is_current`, `sha256`, `size_bytes`, `created_by`, `created_at`.
- Documentar fonte oficial: PDF original, PDF assinado atual, histórico de versões.
- Nunca sobrescrever fisicamente o original.

## 4. RLS do comprador (CRÍTICO)
- Bucket `motorcycle-documents` hoje é vinculado ao proprietário; comprador ainda não é dono.
- Escolher entre:
  - **A. Upload mediado pelo servidor** (server function grava no storage).
  - **B. Signed upload URL temporária** restrita ao `receipt_id`.
  - **C. Política RLS específica** para partes do recibo — só se garantir estritamente: `auth.uid()` = seller/buyer, `receipt_id` pertence à `motorcycle_id`, processo ativo, caminho == recibo.
- Nunca liberar acesso genérico do bucket a compradores.

## 5. Não confiar no frontend
Backend valida MIME real, tamanho, hash, `receipt_id`, `motorcycle_id`, papel, status, caminho, existência do objeto. Não aceitar `storagePath` cego.

## 6. Upload em duas etapas
1. `prepareSignedReceiptUpload(receiptId, fileName, sizeBytes)` — autentica, valida recibo/papel/status, gera caminho e autorização temporária.
2. `finalizeSignedReceiptUpload(receiptId, uploadedObject, sha256)` — verifica objeto, cria nova versão em `motorcycle_documents`, marca anterior como não atual, atualiza `signed_document_received_at`, audita.
- Só atualizar `signed_document_received_at` após confirmação real do objeto.

## 7. Atomicidade
Bloquear recibo/versões, identificar atual, calcular próxima, marcar antiga `is_current=false`, inserir nova `is_current=true`, atualizar `signed_document_received_at`, registrar `audit_log` — tudo transacional. Avaliar índice único parcial (`is_current=true` único por `receipt_id`+`doc_type`). Tratar concorrência.

## 8. Linguagem
Nunca "substituir o documento existente". Usar: "Adicionar documento assinado como nova versão?" e "O documento original permanecerá disponível no histórico."

## 9. Reenvio
Permitir nova versão apenas se processo ativo, usuário autorizado e confirmação explícita. Versão anterior permanece no histórico.

## 10. `completed`
Sem upload comum. Só visualização/download histórico. Correções via fluxo administrativo separado com auditoria reforçada.

## 11. Ações da Central por estado
- **Sem assinado**: "Aguardando assinatura das partes" → Visualizar · Anexar assinado · Cancelar.
- **Com assinado**: "Documento assinado recebido" → Visualizar assinado · Visualizar original · Baixar · Compartilhar · Cancelar (enquanto permitido).
- **Concluído**: Visualizar histórico · Visualizar assinado · Baixar.

## 12. Visualizador
`?version=original|signed`. Default: `signed` se existir, senão `original`. Só entrega versão permitida ao usuário.

## 13. Histórico

## 14. Auditoria
